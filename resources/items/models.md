## Rules

- Models declare relationships, query scopes, `casts()`, mass assignment, route keys, constants, and property types. Accessors compute only from loaded attributes; they do not query or lazy-load relationships. Relationships and scopes build queries without executing them.
- Every model has a class-level PHPDoc block documenting its dynamic properties. Use `@property` for writable attributes and `@property-read` for read-only computed attributes and relationship properties. Types match the model's casts, nullability, and related model or collection types.
- Queries, writes, existing-model decisions, and business behavior belong in actions. Do not add model or `app/Concerns` helpers that execute database operations. Do not hide business queries or writes in model events, boot hooks, or observers.
- Entity models use `HasUuids`; pivot and lookup models keep integer keys. Match the actual schema and preserve existing identifiers and authentication behavior. Cast string enum columns to their backed enum in `casts()`.
- On Laravel 13+, declare actual mass-assignable column names with `#[Fillable]`. Use attributed `#[Scope]` local scopes on framework versions that support them. On older versions, preserve supported mass-assignment and scope declarations; do not upgrade Laravel to apply these conventions.

Use the `laracanon-models` skill for implementation and version-specific choices.

## Skill

Use this **Laracanon-authored workflow** when creating or refactoring an Eloquent model. It supplies guidance without adding dependencies or changing application models automatically.

1. Read the model, related migrations, relationships, traits, casts, factories, actions, authorization, and Resource factories that consume it. Inspect the installed `laravel/framework` version before choosing syntax. For an existing User, retain its authentication base class, existing authentication/notification traits, hidden fields, casts, connection, and route binding. Refactor the requested concern rather than replacing the whole class or converting established IDs.
2. Match the model to its schema. New entity models use `Illuminate\Database\Eloquent\Concerns\HasUuids` with a UUID primary key; pivot and lookup models retain integer IDs. A pivot's own integer ID does not change the UUID type of a foreign key referencing an entity. Use the existing route key deliberately. Coordinate any approved key change through a separate migration and caller update; do not silently convert existing tables or routes. Consult Laravel's [UUID key documentation](https://laravel.com/docs/13.x/eloquent#uuid-and-ulid-keys).
3. Declare only the actual columns the action may mass-assign. On Laravel 13+, import `Illuminate\Database\Eloquent\Attributes\Fillable` and use `#[Fillable(['name', 'email', 'phone_number', 'password'])]` for the accepted User creation flow. Preserve the existing `$fillable`/`$guarded` declaration on Laravel 11/12 rather than importing an unsupported attribute. Keep unrelated sensitive fields protected; the convention does not authorize a blanket unguarded model. The [mass-assignment documentation](https://laravel.com/docs/13.x/eloquent#mass-assignment) and official [Laravel 13 attribute source](https://github.com/laravel/framework/blob/v13.0.0/src/Illuminate/Database/Eloquent/Attributes/Fillable.php) define this API.
4. Define typed relationships that return their Eloquent relationship builders. Add local scopes only for reusable query composition. On Laravel 12.4+ and 13, import `Illuminate\Database\Eloquent\Attributes\Scope` and declare a protected attributed method, such as `active(Builder $query): Builder`, returning the same builder after adding its predicates. On Laravel 11 or 12.0–12.3, use the supported public `scopeActive(Builder $query): Builder` convention. Call either form from an action as `User::query()->active()`, and execute the terminal operation in that action. Do not call `get()`, `first()`, `exists()`, `count()`, or writes inside the scope or relationship declaration. The attribute first appears in official [Laravel 12.4.0 source](https://github.com/laravel/framework/blob/v12.4.0/src/Illuminate/Database/Eloquent/Attributes/Scope.php); [Laravel 11 local scopes](https://laravel.com/docs/11.x/eloquent#local-scopes) use the prefixed method. No framework upgrade is required.
5. Keep casts and accessors local to already-loaded values. In `casts()`, map an existing string enum column such as `status` to its backed enum class, keeping other casts intact. An accessor may read the attributes provided to its `Attribute` getter, but it must not fetch missing attributes or query relations. If output needs a related field or count, have the read action select and eager-load it before the Resource reads it. Preserve the existing selected-field contract; a computed accessor is not permission to query around it. See Laravel's [accessor and casting documentation](https://laravel.com/docs/13.x/eloquent-mutators).
6. Add or update the model's class-level PHPDoc block alongside its schema, casts, accessors, and relationships. Document writable attributes with `@property`, such as `@property string $name` and `@property string|null $phone_number` in the User flow. Use `@property-read` for read-only computed attributes and relationship properties. A singular relationship names its related model and allowed nullability; a plural relationship names its Eloquent collection with key and related-model generics. Use the cast's exposed PHP type for dates, booleans, and enums. Include only real properties, keep existing useful annotations, and update the block when those contracts change; the annotations do not authorize lazy loading or grant mass-assignment access.
7. Trace model helpers, traits, observers, and boot hooks before moving business work. Put the operation in the appropriate typed action, update its real callers, and retain the existing transaction, authorization boundary, and after-commit delivery. Do not remove framework lifecycle support such as UUID generation, casts, timestamps, or authentication traits merely because they run internally. The rule concerns hidden application business queries and writes, not Eloquent's own persistence mechanisms.
8. Run the application's focused model/action checks for key generation and type, allowed/protected assignment, casts, route binding, relationships, and scope results. Where an accessor or Resource is involved, verify reading it after the intended attributes are loaded executes no extra queries. Verify moved behavior through its action and callers, including applicable transaction or event timing. Report supported framework syntax, changes made, and any behavior that remains unverified.
